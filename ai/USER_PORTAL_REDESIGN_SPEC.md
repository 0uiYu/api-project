# 用户端重构主控规格

## 0. 文件用途

本文件是用户端 UI 重构的主控依据。执行本任务的 AI 必须先完整阅读本文件，再阅读设计原型和相关源码。本文件第 14—18 节是审阅后修订，若与前文冲突，优先遵循修订；不得同时实现相互矛盾的要求。

目标是让普通用户端脱离 New API 的后台控制台结构，围绕用户完成 API 调用的核心业务链，重构成简单、简约、清晰的开发者门户。

设计原型：

- `ai/ui-prototype/user-portal-concept.html`
- `ai/ui-prototype/auth-and-landing-concept.html`

本任务只重构普通用户端。管理员仍然使用完整的后台侧边栏和管理页面。

## 1. 核心业务链

普通用户真正需要完成的流程是：

```text
登录
  ↓
查看账户状态
  ↓
选择模型
  ↓
创建 API Key
  ↓
复制 API 地址和 SDK 代码
  ↓
发起 API 请求
  ↓
查看余额、用量和请求明细
```

用户端页面必须服务于这条链。页面中的每个主要区块都必须能回答以下问题之一：

- 我现在的账户状态是什么？
- 我应该选择哪个模型？
- 我如何开始调用？
- 我用了多少？
- 我如何管理账户？

## 2. 用户端导航

普通用户使用顶部导航，不使用左侧后台侧边栏。

桌面端导航必须是：

```text
品牌 | 首页 | 找模型 | 接入 API | 我的用量 | 我的账户 | 文档 | 通知 | 语言 | 用户菜单
```

移动端使用横向滚动导航或折叠菜单，但菜单名称和顺序不能改变。

导航项与路由映射：

| 菜单 | 路由 |
|---|---|
| 首页 | `/dashboard` |
| 找模型 | `/model-square` |
| 接入 API | `/keys` |
| 我的用量 | `/usage-logs` |
| 我的账户 | `/profile` |
| 文档 | `/about` |

管理员判断：`user.role >= ROLE.ADMIN`。管理员继续使用 `AppHeader + AppSidebar`，普通用户使用 `UserPortalHeader`。

## 3. 设计系统

### 3.1 页面基础尺寸

- 用户端页面最大内容宽度：`1120px`
- 页面左右内边距：桌面端 `28px`，移动端 `18px`
- 顶部导航高度：`68px`
- 页面背景：`#F5F7FA`
- 卡片背景：`#FFFFFF`
- 卡片边框：`#E5EAF1`
- 主文字：`#182235`
- 次要文字：`#758197`
- 主色：`#315CCE`
- 主色浅背景：`#EDF3FF`
- 卡片圆角：`14px`
- 卡片内边距：`22px`
- 卡片之间的标准间距：`16px`
- 默认阴影：无；只有弹层可以使用阴影

### 3.2 卡片规则

设计图中的信息卡片必须满足：

```text
白色背景
1px #E5EAF1 边框
14px 圆角
22px 内边距
无阴影
```

禁止使用：

- `bg-card/70`
- `bg-card/80`
- 大范围渐变卡片
- 后台蓝色顶部边框
- 每张卡片内部放多个操作按钮

### 3.3 用户端文字规则

用户端使用任务语言，不使用后台管理语言：

| 禁止作为主标题 | 使用 |
|---|---|
| Dashboard | 首页 |
| Model Square | 找模型 |
| Usage Records | 我的用量 |
| Profile | 我的账户 |
| Token Management | 接入 API |
| Vendor | 供应商，仅在详情中出现 |
| Endpoint Type | 接口类型，仅在详情中出现 |

所有新增文案必须通过 `useTranslation()` 的 `t()` 渲染，并同步 `en.json`、`zh.json`（界面只发布英文和简体中文）。

## 4. 首页规格

源码入口：

- 路由：`web/src/routes/_authenticated/dashboard/$section.tsx`
- 页面：`web/src/features/dashboard/components/overview/overview-dashboard.tsx`
- 指标：`web/src/features/dashboard/components/overview/stat-cards.tsx`

### 4.1 页面结构

首页只能按照以下顺序展示：

```text
欢迎标题
欢迎副标题
三个快捷操作
四个状态卡片
最近使用的模型
快速开始
```

页面不使用旧的 `SectionPageLayout.Title` 标题栏。首页必须是独立的用户端内容容器。

### 4.2 欢迎区

```text
欢迎回来，今天想做什么？
只保留选择模型和开始构建所需要的信息。

[找一个模型] [创建 API Key] [查看用量]
```

快捷按钮必须放在欢迎区，不得放进余额卡片。

### 4.3 四张状态卡片

固定顺序：

1. `账户余额`
2. `今日请求`
3. `API Keys`
4. `最近使用`

卡片不能放图标徽章，不能放充值按钮，不能放创建 Key 按钮。

卡片内部结构：

```text
小号标签
大号数值
小号描述
```

真实数据映射：

- 账户余额：`auth.user.quota`，使用现有 `formatQuota`
- 今日请求：`getUserQuotaDates`
- API Keys：`getApiKeys`
- 最近使用：如果后端没有最近调用时间接口，显示稳定的空状态或最近活动入口，不得伪造真实时间

### 4.4 最近模型和快速开始

下方使用两列布局：

```text
左列：最近使用的模型
右列：快速开始
```

左列只显示模型名称和简短能力标签，不显示价格表、供应商、端点和复杂统计。

右列固定三步：

```text
1. 选择模型
2. 创建 API Key
3. 阅读 API 文档或发送第一次请求
```

## 13. 执行纪律

如果现有页面结构与本文件冲突，优先重构页面结构，不要继续在旧结构上叠加样式。

如果设计图中的静态示例和真实 API 数据冲突，保留设计图的布局，使用真实数据；没有真实数据时显示空状态，不得伪造数据。

每完成一个页面，必须说明：

3. 删除或降级了哪些旧内容。
4. 执行了哪些验证。

## 14. 最高目标与设计依据（优先于前文）

最高目标：让用户用最少的理解成本和操作步骤完成接入、调用和查账。简约不是少显示文字，而是减少需要用户自己判断的选项、重复入口和无用状态。

HTML 原型是已确认的视觉基准：尺寸、白色卡片、字体、留白和排列要对照实施。它不是已完成的业务设计：原型里没有实现的搜索、标签、设置、价格和数字不能直接变成生产功能或生产数据。

参考文件的工作区绝对路径（换机器时按仓库相对路径定位）：

- `H:\桌面\API\api-project\ai\ui-prototype\user-portal-concept.html`
- `H:\桌面\API\api-project\ai\ui-prototype\auth-and-landing-concept.html`

介绍页当前视觉已获用户认可，只轻微统一品牌和入口。不要再次大改介绍页。当前请求重点是用户登录后的核心体验。

新方案如果需要改变已确认的导航数量或主要布局，先交付可比较的原型，不直接实施。不能用“优化体验”为理由自由增加推荐系统、会员等级、项目管理或新的业务模块。

## 15. 功能分层与减少重复

| 层级 | 功能 | 展示方式 |
|---|---|---|
| 核心 | 选模型、创建/复制 Key、复制地址和代码、余额、充值、消耗、请求失败原因 | 默认可见 |
| 进阶 | Key 限额、有效期、模型权限、价格细项、请求详情 | 更多设置或详情 |
| 附加 | 签到、推广、订阅、界面偏好 | 账户次级入口，按系统启用状态显示 |
| 管理 | 渠道、供应商管理、系统设置、全站分析 | 仅管理区域 |

默认每个页面只突出一个主操作：模型页为选择/复制模型，接入页为创建或复制 Key，用量页为查消耗，账户页为修改资料或安全设置。页面出现同样的按钮两次时，必须说明必要性，否则删除重复。

首页快捷按钮与三步说明存在重复。三步说明只在没有 Key 或没有成功调用的新用户状态显示；已有调用的用户展示最近真实活动。欢迎副标题不写“只保留必要信息”等描述界面设计过程的文案。

充值属于核心链，不能因为压缩导航而让用户找不到：账户余额附近提供清晰的充值入口，可以放在余额区域外，不强制塞进每张指标卡。

## 16. 真实数据与可执行交互

先从前端调用追踪到后端路由、控制器和响应类型，再确定能显示哪些数据。前文列出的接口是阅读入口，不代表它们足以支撑所有指标。

- “最近使用的模型”必须来自该用户实际请求，不得写死三个模型或把热门模型假装成最近使用。
- 余额、今日、本月、过去 30 天是不同时间范围，必须传明确时间参数并标明范围。
- `/api/log/self/stat` 当前响应类型包含 quota、rpm、tpm；不能用它直接宣称已经获得总请求数、Token 总量或成功率。需要检查其他聚合接口和后端统计口径。
- 本月不能直接用过去 30 天替代；如果接口不支持本月范围，使用实际支持的周期并修改标题，不隐瞒限制。
- 成功率需要可靠的成功数/总请求数及相同周期。数据不足显示“暂无数据”，禁止从少量分页记录计算全周期成功率。
- 加载中显示骨架或加载状态；请求失败显示错误和重试；不能把失败、未加载或缺失数据显示成 0。
- 默认模型没有真实读写能力就不展示成已保存设置，禁止写死 `gpt-4.1-mini`。
- SDK 示例必须使用实际配置的 API 地址和可用模型，并有完整 messages 参数。Key 使用明确占位符，不把完整密钥自动写入截图、日志或页面源代码。
- 代码可复制且可执行；不以 `api.example.com` 占位示例声称完成接入。
- 搜索框如果只有关键词匹配，提示写“搜索模型名称”，不能宣称支持自然语言需求搜索。
- “代码/推理”筛选需要可验证的能力标签；“快速”需要可靠速度数据和比较规则，没有数据就暂不提供。“便宜”需定义币种、计费单位和阈值。
- 不同计费类型必须标明按 Token、按次或按任务，不能强制所有模型套用输出 Token 价格。

账户“基本资料”要显示真实用户名和邮箱，并复用实际编辑能力；不能用“管理个人资料”卡片替代真实内容。安全标签复用已有安全功能，避免再放一张说明卡片让用户跳两次。

## 17. 交互、主题与响应式

- 优先复用现有业务封装，不为换样式重写创建 Key、复制、确认、分页和验证逻辑。
- 创建 Key 默认只要求完成调用所必需的字段；限额、有效期、权限等放入可展开的进阶设置，服务端校验和默认安全语义保留。
- 模型选定后进入接入页时携带模型选择，代码示例同步更新，不要求用户再找一次模型。
- 用量默认查成本趋势，明细按时间、模型、状态筛选；详情展开再显示技术字段，保留请求 ID 和失败原因以便排错。
- 没有 Key、没有调用、没有模型、低余额、请求失败各有明确下一步，空状态不堆统计卡片。
- 顶部显示当前页面；Tab 使用共享 Tabs 并支持键盘和焦点状态；操作按钮要有可访问名称。
- 375px、768px、1440px 下不发生页面级横向溢出。代码和表格可在自身区域横向滚动；页面优先使用单一主滚动区域，避免多个高度受限的嵌套滚动框。
- 明亮主题按原型使用纯白卡片；深色主题提供一致的深色文字/背景变量，禁止硬塞白色卡片却继承白色文字。不要用逐组件 `dark:bg-white` 作为完整主题方案。
- 统一页面级设计变量，不在多个组件复制颜色长串；不污染管理端和公共页面。
- 两种语言显示语义一致，长文本可换行；日期、金额、数字继续使用项目格式化封装。

## 18. 分阶段交付与验收证据

第一阶段只做只读审计：输出业务链、每个动作的前后端文件与接口、真实响应字段、保留/降级功能清单、原型和当前实现差异。不在审计阶段删除业务。

第二阶段按页面实施：先共用布局，再首页、模型、接入、用量、账户。每页完成必须和原型对照，不能把“换标题/颜色”报告为主体重构完成。

第三阶段验证：

1. 新用户能找到模型、创建 Key、复制正确地址和完整代码。
2. 老用户能直接找到已有 Key、余额和最近真实调用。
3. 用户能找到充值入口，并查看同一周期的消费及具体失败请求。
4. 用普通用户及管理员分别验证，不能只登录管理员来验收用户端。
5. 对五页分别保存桌面/移动端截图；代表页面检查浅色/深色及中文/英文。
6. 在相同视口比较原型和 React 的宽度、卡片数量、背景、圆角、字号及区块间距，记录真实数据或业务需要导致的差异。
7. 跑受影响行为测试、类型检查、修改文件 lint 和最终构建。编译通过不等于视觉和交互通过。

没有浏览器验证条件时明确列出未验收项目，继续完成可验证工作，但不能声称“一比一完成”。不能要求用户反复发现同类间距、卡片背景和结构问题来代替自检。

最终交付报告必须列出完成项、未完成项、实际执行的检查、截图路径和已知限制。禁止用“还有下一轮”掩盖已承诺但未完成的范围；不得未授权提交、推送或上线。
