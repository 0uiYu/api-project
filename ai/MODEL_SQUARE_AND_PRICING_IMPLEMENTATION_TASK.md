# 模型广场与价格展示改造任务

## 任务目标

改造用户端模型广场，并增加后台手动维护官方参考价格的能力。不得只修改前端视觉；必须保证后端数据、管理员配置、用户端展示和价格语义一致。

## 已确定的业务规则

### 供应商、渠道和模型

- 用户端将渠道以“供货商”名称展示。
- 管理后台仍保留“渠道”概念，因为一个供货商可能有多个实际渠道。
- 用户端供货商分类至少包括：Claude、ChatGPT、Grok、Gemini、其他。
- 供货商代码使用稳定的内部值，例如：`anthropic`、`openai`、`xai`、`google`、`other`；展示名称必须通过 i18n 渲染。
- 模型列表必须来自后端真实数据，禁止在前端写死模型名称。
- 模型和供货商都应显示图标；优先复用项目现有图标能力。

### 价格

价格分为两套：

1. 网站销售价格：由现有模型、渠道、倍率和计费配置计算。
2. 官方参考价格：由管理员手动维护，仅用于用户端参考展示，不参与实际扣费。

两套价格都要支持以下四种字段：

- 输入价格
- 输出价格
- 缓存读取价格
- 缓存创建价格

要求：

- 官方价格可以为空，空值显示“暂无官方参考价”。
- `0` 表示确实免费，不能把 `0` 当成未配置。
- 不支持缓存的模型允许缓存字段为空。
- 官方价格不能写死在前端，也不能从网页文本临时抓取。
- 后端最终扣费只使用网站实际配置，不使用客户端提交的价格或倍率。

### 用户分组和渠道分组

- 本次用户端不展示“用户分组”“渠道分组”等后台术语。
- 不删除后端现有分组能力；它仍可作为渠道权限和路由扩展能力保留。
- 用户不能通过前端自行提高倍率、切换到未授权渠道或修改价格。

## 用户端模型广场

### 筛选区域

按从左到右的顺序展示：

1. 供货商筛选：Claude、ChatGPT、Grok、Gemini、其他。
2. 模型筛选：全部模型及后端返回的模型名称。
3. 倍率筛选：读取后端真实倍率，不能写死倍率枚举。

筛选项应直接展示，不要把主要筛选项全部隐藏在二级菜单中。移动端允许横向滚动或换行，但不能产生页面级横向溢出。

搜索仍然支持模型名称搜索。筛选条件必须能组合使用，并支持清除。

### 模型列表

模型广场下方使用列表式展示，不使用当前卡片网格作为默认视图。

每条记录至少展示：

- 模型图标
- 模型名称
- 供货商图标和名称
- 网站价格：输入、输出、缓存读取、缓存创建
- 官方参考价格：输入、输出、缓存读取、缓存创建
- 倍率

不要在模型记录中展示“可用/不可用”状态。模型列表的职责是展示模型和价格，不承担渠道健康状态展示。

对于按次、任务或图片计费模型，必须沿用现有计费类型和单位，不能强行套用 Token 价格字段。

## 渠道状态导航

新增独立的“渠道状态”入口或导航页，不把渠道状态混入模型列表。

渠道状态页展示真实渠道数据，例如：

- 供货商名称
- 渠道名称
- 渠道类型
- 当前状态
- 最近检测时间
- 延迟（如果后端真实提供）
- 失败原因或错误信息（如果后端真实提供）

禁止伪造延迟、检测时间或健康状态。后端没有提供的数据应显示“暂无数据”。

## 管理后台

在现有模型/模型价格编辑流程中增加官方参考价格编辑能力：

- 官方输入价格
- 官方输出价格
- 官方缓存读取价格
- 官方缓存创建价格

要求：

- 使用现有表单、校验、权限和保存流程。
- 只有有权限的管理员可以修改官方价格。
- 修改后 `/api/pricing` 或对应定价接口返回最新字段。
- 数据库迁移必须兼容 SQLite、MySQL 和 PostgreSQL。
- 迁移必须幂等，并保留已有价格数据。

如果项目现有模型价格是配置映射而不是独立模型表字段，优先扩展现有配置体系，避免重复建立第二套价格来源；但官方价格必须与网站实际扣费价格明确区分。

## API Key 与渠道选择边界

如果本次同时修改 API Key 创建弹窗，可以展示管理员允许用户使用的供货商/渠道选项及倍率，但必须满足：

- 前端选择只提交渠道标识，不提交可信价格或倍率。
- 后端验证渠道已启用、支持请求模型、且当前用户/API Key 有权使用。
- 实际请求使用后端渠道配置的上游地址、上游 Key、模型映射和倍率。
- 用户不能通过修改请求体将倍率改低或选择未授权渠道。
- 如果一个 Key 允许多个渠道，必须明确首选/备用顺序；第一版优先支持一个 Key 绑定一个默认渠道，避免扣费和故障切换口径不清。

## 实施顺序

1. 检查当前定价接口、模型元数据、渠道状态接口和管理员模型编辑流程。
2. 增加官方四类价格的数据字段和后端读写能力。
3. 增加管理员手动编辑官方价格的表单和校验。
4. 扩展定价响应类型，返回网站价格、官方价格、供货商和倍率信息。
5. 改造用户端筛选区域。
6. 将模型广场默认视图改为列表，移除模型列表中的可用状态。
7. 增加独立渠道状态导航/页面。
8. 按需改造 API Key 创建弹窗的渠道选项，但不绕过后端权限校验。
9. 同步中英文 i18n 文案。
10. 执行类型检查、lint、相关单元测试、Go 测试和前端构建。

## 禁止事项

- 不得伪造官方价格、渠道延迟、渠道健康状态或最近检测时间。
- 不得把官方参考价格用于实际扣费。
- 不得只修改前端而不修改后端数据接口。
- 不得让用户自行选择 VIP、代理或内部倍率。
- 不得删除现有管理员渠道配置、模型映射和计费逻辑。
- 不得把缓存未配置显示成免费。
- 不得新增重复的 API 请求和模型数据源。
- 不得修改与本任务无关的支付、邀请、兑换码业务。

## 验收标准

- 用户端可按供货商、模型、倍率组合筛选。
- 供货商和模型有图标，名称来自真实数据或稳定元数据。
- 模型默认以列表展示。
- 每条模型记录能区分网站价格和官方参考价格。
- 输入、输出、缓存读取、缓存创建四类价格均可展示。
- 官方价格为空、为 0、已配置三种情况显示正确。
- 模型列表不再显示渠道可用状态。
- 渠道状态在独立页面展示，并且没有伪造数据。
- 普通用户无法通过前端参数修改真实扣费倍率或越权使用渠道。
- SQLite、MySQL、PostgreSQL 的数据库变更兼容且可重复执行。
- 中英文文案完整。
- `bun run typecheck`、相关 lint、相关测试和前端 build 通过。

## 交付报告必须包含

- 修改的文件和每个文件的作用。
- 新增或修改的 API、字段和数据库迁移。
- 网站价格与官方参考价格的数据来源。
- 渠道状态的数据来源；没有数据的字段必须明确说明。
- 执行过的验证命令和结果。
- 尚未实现或无法验证的内容，不得用“已完成”替代。
