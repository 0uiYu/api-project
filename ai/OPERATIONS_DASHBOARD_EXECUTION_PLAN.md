# 全屏运营数据看板执行计划

## 目标

把管理员进入 `/dashboard/overview` 后看到的页面改造成 API 中转站运营驾驶舱：在一页内呈现请求、模型、计费估算、渠道健康、用户与兑换业务，并保留可下钻到明细页面的能力。

## 不改变的边界

- 不删除后端已有订阅、任务插件和支付实现；本次只调整管理端入口和看板展示。
- 不把官方参考成本伪装成真实供应商成本。
- 不把加载失败、接口失败或成本缺失显示为 0。
- 不在前端重新计算实际扣费；扣费以日志和后端结算结果为准。
- 不新增未经确认的供应商绑定或渠道绑定业务。

## 阶段 0：现有功能基线

- 阅读现有管理员概览、模型分析、收入分析、用户分析和流量分析组件；
- 列出已有接口、字段、权限和时间范围；
- 区分可以复用的数据和必须新增的数据；
- 固定当前前端类型检查、相关单测和后端构建结果。

验收：形成接口字段矩阵，确认每个看板模块的数据来源。

## 阶段 1：统一看板数据协议

优先复用现有接口：

- `/api/admin/analytics/usage-summary`：请求、Token、扣费、参考成本；
- `/api/perf/metrics/summary`：成功率、延迟和吞吐；
- `/api/channel-status`：渠道健康状态；
- `/api/admin/affiliate/stats`：邀请数据；
- `/api/data`：额度和趋势数据；
- 现有模型统计接口：模型排行和调用趋势。

只有现有接口不能提供的数据，才新增聚合接口。新增接口必须使用管理员认证，并明确 `hours` 或时间戳范围。

统一响应状态：

```text
loading / success / empty / error
```

验收：没有一个卡片依赖多个接口后把缺失值误合并成 0。

## 阶段 2：全屏布局和全局控制栏

页面结构：

```text
全屏运营概览
├── 时间范围
├── 刷新间隔
├── 手动刷新
├── 导出入口
├── 全屏/退出全屏
├── 异常摘要
├── 核心指标
├── 请求与模型分析
├── 收入与成本估算
├── 渠道健康
└── 用户与兑换业务
```

时间范围统一支持：1 小时、今日、7 天、30 天、自定义。所有子模块共享同一个范围。

验收：切换时间范围后所有卡片和图表使用相同 start/end timestamp。

## 阶段 3：核心指标区

首屏显示：

- 请求总数；
- 成功率；
- 失败请求；
- 用户实际扣费额度；
- 输入 Token；
- 输出 Token；
- Cache Read；
- Cache Write；
- 活跃用户；
- 异常渠道；
- 估算收入；
- 参考成本。

所有卡片支持点击下钻到对应明细页面。

## 阶段 4：图表区域

请求与模型：

- 请求量/成功率趋势；
- 模型调用排行；
- 模型消耗排行；
- 输入/输出/cache 趋势；
- 平均延迟和失败原因。

收入与成本：

- 用户实际扣费趋势；
- 官方参考成本趋势；
- 估算毛利趋势；
- 成本不可用数量；
- 充值和兑换码趋势。

渠道健康：

- 正常/异常/自动禁用数量；
- 渠道响应时间；
- 渠道错误率；
- 最近失败渠道。

## 阶段 5：异常和联动

异常摘要显示：

- 失败率超过阈值的模型；
- 异常渠道；
- 发放失败的兑换订单；
- 成本缺失的模型；
- 统计接口失败。

点击异常直接跳转到渠道、使用记录、兑换订单或模型页面，并保留筛选条件。

## 阶段 6：性能和响应式

- 图表按需加载；
- 同一接口请求去重；
- 默认 60 秒刷新；
- 支持关闭、30 秒、1 分钟、5 分钟；
- 桌面端全屏驾驶舱；
- 窄屏端改为单列，不强行压缩图表；
- 禁止高频轮询造成日志表压力。

## 阶段 7：权限、国际化和可访问性

- 普通用户不能访问管理员聚合接口；
- 管理员菜单与页面权限一致；
- 所有标题、状态、错误提示进入中英文语言包；
- 图表必须有文字摘要或可访问标签；
- 全屏按钮、刷新按钮和异常状态支持键盘操作。

## 阶段 8：验证和交付

- 前端类型检查；
- 看板组件单元测试；
- 时间范围联动测试；
- loading/error/empty 测试；
- 管理员权限测试；
- 前端生产构建；
- 后端构建；
- Docker 嵌入前端构建说明；
- 最后再提交和推送。

当前状态：阶段 0 已完成；阶段 1/2/3/4 已落地。管理员运营概览已合并核心调用、模型趋势、消费分布、收入/成本估算、渠道健康度，并支持时间范围、手动刷新、全屏模式。正在执行最终验证。
